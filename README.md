# 本地小端 PCAP · TCP 重组查看器（限定版）

纯浏览器实现：读取**不超过 8 MB、2000 个包**的限定版经典 PCAP，**只解析小端 PCAP /
以太网（Ethernet II）/ IPv4 / TCP**，按双向四元组归并端点对、并在同一四元组内按
SYN/FIN/RST 与序号事实拆分多次 TCP 会话后逐流重组字节。文件**从不上传**，
全部解析在 Web Worker 内于本机完成。

## 运行

```bash
cd src
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000/
```

> 需经本地静态服务器打开（Web Worker 在 `file://` 下通常被禁止）。
> 可把 `samples/demo.pcap`（由 `node test/make-sample.js` 生成）直接拖入页面。

## 功能与保证

- **流与端点对分离（同一四元组多次会话）**：先按归一化双向四元组
  `IP:port <-> IP:port` 归并端点对，再在每个四元组内按**捕获顺序**做会话拆分。
  同一对端点先后建立两次 TCP 连接（端口快速复用）时拆成**两条独立流**，
  各自锚点与序号空间独立重组；第二次会话的字节绝不会被并入第一条流而误报成
  重传 / 冲突 / 缺口。拆分只依据序号与 SYN/FIN/RST 事实，不做完整状态机推断：
  - 已见过 SYN 后再来 SYN：ISN 相同 => 同一连接的重传 SYN；ISN 不同 => 新会话；
  - 会话已双向 FIN 正常关闭、或被 RST 复位后再来 SYN => 一律新会话；
  - RST 归属当前会话并将其终止；FIN 只关本方向（半关闭期间对端数据仍归同一会话），
    双向 FIN 才整体关闭；
  - 关闭后窗口内的迟到重传 / 纯 ACK 仍归旧会话（计重传去重，不凭空造流），
    序号远在窗口之外的数据段才开新会话；
  - 未见握手的单向片段：作为单条“中途捕获”会话独立重组，不猜测连接归属；
  - 未见 FIN/RST 即出现新 SYN：旧会话标记“被新会话取代（未见关闭）”，两段证据都保留。
  - 会话边界事件（关闭 / 复位 / 新建 / 中途捕获）写入该流“异常”面板并进入冻结导出。
- **连接与方向**：每条流按方向独立重组；方向间通过 ack/seq 协同关闭判定。
- **重传去重**：同一流内重叠位置字节完全相同 => 计为重传并去重，不重复计数
  （不同会话之间绝不互相去重）。
- **缺口显式留空**：同一会话内缺失序号区间形成覆盖段（run）之间的 gap，文本中以
  `␠[缺口 N 字节]` 标注、十六进制视图中打印缺口行；**绝不**把缺口两侧内容直接拼接，
  也绝不跨会话拼接。
- **字节冲突**：同一会话内重叠位置字节不一致 => 标记冲突，展示保留“文件中先捕获”的
  字节，并在冲突面板列出每个到达包的包号与实际字节。不凭到达顺序悄悄覆盖；
  不同会话的同序号字节天然不构成冲突。
- **32 位序号回绕**：以每流每方向锚点（优先首个 SYN 的 ISN，否则首个数据段 seq）
  展开序号；按捕获顺序用“最高字节水位（段尾）”解包，正确处理回绕点附近的乱序 /
  重传 / 缺口；回绕事件在“异常”面板显式说明。回绕展开在各会话内独立进行，跨会话
  互不影响。真实跨度达到 2^31（8MB 文件内不可能）会标记歧义，不猜测。
- **页面视图**：按流（会话）、方向查看 包 / 缺口 / 冲突 / 重组文本 / 十六进制 / 异常；
  流列表标注同端点对内的会话序号（如 会话 1/2）与关闭状态（FIN 正常关闭 / RST 复位 /
  被取代 / 未见关闭）；另有“未纳入重组的包”（非 IPv4、非 TCP、IP 分片、snaplen
  截断等）列表。两次会话之间夹杂其他连接的包不影响归属。
- **导出引用冻结结果**：解析完成即对重组结果深拷贝冻结（含全部字节）。
  “导出冻结结果 (JSON)”导出该不可变快照；“导出当前文本”同样从冻结快照读取，
  后续重新导入或任何操作都不会改变它。
- **错误文件头整份拒绝**：魔数不是 `d4 c3 b2 a1`（含大端 pcap、pcapng）、
  链路层非以太网 => 致命错误，整份不展示。
- **截断包留证并停止**：记录头或记录数据在文件尾部被截断时，保留文件偏移、
  `incl_len/orig_len`、剩余字节数等位置证据，停止解析该包（此前包仍可见）。
- **旧 Worker 迟到结果不替换当前文件**：每次导入使用递增会话 token，并
  `terminate()` 旧 Worker；主线程丢弃 token 不匹配的迟到结果；“取消”同样令在途结果失效。

## 文件结构

```
src/
  index.html      页面
  styles.css
  app.js          UI、会话/token 管理、限制校验、冻结导出
  worker.js       Web Worker：本地解析 + 冻结
  pcap.js         小端 pcap / 以太网 / IPv4 / TCP 解析（UMD，Node 可复用）
  reassemble.js   四元组会话拆分（SYN/FIN/RST 复用识别）、每流每方向序号展开与回绕、
                  去重/缺口/冲突、冻结（UMD）
test/
  run-tests.js    Node 对拍测试（乱序/回绕/重传/缺口/冲突/截断/拒绝/多次会话拆分…）
  make-sample.js  生成 samples/demo.pcap（同一端点对两次会话：FIN 关闭 + RST 复位）
samples/demo.pcap 演示样本（生成物）
```

## 运行测试

```bash
node test/run-tests.js     # 对拍用例
node test/make-sample.js   # 重新生成演示样本
```

## 明确不做的事

- 不解析 pcapng、大端（字节交换）pcap、非以太网链路层。
- 不解析 IPv6、UDP 等非 TCP 协议；IP 分片不参与 TCP 重组。
- 不校验 TCP/IP 校验和（抓包常置零）。
- 不做完整 TCP 状态机推断（不追踪窗口 / 定时器 / 重传队列）；会话拆分只依据
  SYN/FIN/RST 控制位与序号事实。没有任何 SYN/FIN/RST 证据时，不按序号跳跃猜测
  会话边界——该段作为单条“中途捕获”流展示，缺失就是缺口，避免把真实丢包误拆成连接。
